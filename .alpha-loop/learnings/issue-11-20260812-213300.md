## What Worked
- Kept the standalone application canonical by generating its routes from a pure core manifest and layering validated extension contributions around those routes.
- Built the same web source as both a Vite application and an externalized library entry without publishing a package.
- Exercised the extension seam with a fixture identity, policy, route, navigation item, and settings section.

## What Failed
- The full `pnpm verify` command reached one sandbox-only failure because the browser daemon posture test invokes `/bin/ps`, which this worker cannot execute. Every remaining test and build command passed when run directly.

## Patterns
- Keep the canonical product-boundary inventory independent from the implemented route manifest so automated comparison detects removed or changed core surfaces.
- Treat extension metadata as untrusted runtime input even when private consumers also compile against strict TypeScript contracts.

## Anti-Patterns
- Do not derive the required boundary inventory from the implemented manifest; changing both from one source would make surface-removal checks self-fulfilling.
