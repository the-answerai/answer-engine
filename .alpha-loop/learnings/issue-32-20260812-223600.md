# Issue #32 — patch active dependency advisories

## Consumer-resolution lesson

An OSS lockfile can resolve a safe version while a downstream workspace still
selects an older vulnerable release from the same permissive semver range. The
public package declaration must encode the security floor; checking only the
source repository lockfile does not protect consumers.

## Audit lesson

The first reported package was not the complete production exposure. After the
React Router and Vitest updates, a full production audit found high-severity
transitives under both OpenAI and the MCP SDK. Narrow root overrides now hold
those transitive packages at their patched releases until their parents carry
safe constraints, and a repository test preserves every known floor.

## Verification lesson

Security dependency repairs must combine three proofs: manifest floors for
future consumers, frozen-lock resolutions for this checkout, and a production
audit with zero high or critical findings. Routing, API, CLI, MCP, and browser
checks still run because a clean advisory report cannot prove compatibility.
