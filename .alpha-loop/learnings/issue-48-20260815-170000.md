## What Worked
- Kept Electron as a thin control plane over the installer's existing guarded lifecycle and channel profiles.
- Used an in-memory fixture for every visual and packaged-app interaction, including URL, log-folder, and login-item controls.
- Served a tiny renderer from a privileged local scheme with sandboxing, context isolation, a strict CSP, sender validation, and no renderer Node access.
- Built and checksum-verified bounded temporary artifacts, then immediately reclaimed their disk space with an exact-path cleanup command.

## What Failed
- The initial builder output path climbed one directory too far and placed 283 MB beside the issue worktree. The output is now rooted in the worktree's ignored `tmp/desktop-release`, and packaging tests pin that exact relative path plus the cleanup path guards.
- The first checksum verification ran from the repository root even though standard `SHA256SUMS` entries are relative to the artifact directory. The release guide now runs verification from that directory.
- The first focused test run inherited the repository root's Vitest include pattern and found no desktop tests. A package-local Vitest configuration and desktop lint/type/test gates now run in `pnpm verify`.
- The first manual PR creation targeted `master` even though active epic children aggregate into the session branch. A pre-merge `baseRefName` audit caught and corrected it before merge; every remaining epic PR must repeat that audit.

## Patterns
- Desktop UI fixture mode must replace every external adapter, not only the core runtime controller.
- Window lifetime, tray lifetime, and background runtime lifetime are three separate concerns and should have separate evidence.
- Release artifact generation needs an explicit space budget, an ignored bounded destination, and safe cleanup in the same workflow.
- Keep platform signing configuration and clean-hardware proof distinct: local unsigned inspection can validate contents, but cannot claim signed Windows acceptance.

## Anti-Patterns
- Do not duplicate upgrade or rollback logic in Electron or let the renderer supply arbitrary image references.
- Do not expose raw IPC, shell, filesystem, or lifecycle objects through preload.
- Do not treat a successful development-mode Electron launch as packaged-application verification.

## Suggested Skill Updates
- Add a mandatory fixture-side-effect audit to Electron visual verification.
- Add builder output-path resolution, peak disk measurement, checksum CWD, and cleanup verification to desktop packaging checklists.
