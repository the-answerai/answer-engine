# Issue #10 setup interruption: fail closed on stale browser daemons

## What happened

The mandatory `pnpm browser:prepare` setup command failed before issue #10
planning because the shared agent-browser daemon survived issue #9 cleanup.
Its executable and current working directory both lived in the removed issue #9
worktree. Alpha Loop warned and continued, so the supervisor stopped the run.

## Root cause

`agent-browser close` closes Chrome sessions but intentionally leaves the daemon
alive. Persisting the socket and browser profile under `/tmp` made the daemon
reachable across worktrees, but did not make its worktree-local executable or
working directory durable.

## Prevention

- Treat setup commands as mandatory gates and stop before planning on failure.
- Reset only the validated project-scoped daemon before every host preflight.
- Exercise the complete lifecycle in regression coverage: an old worktree
  daemon must be terminated before the next worktree opens Chrome.
- Resume the preserved issue worktree only after the repair is merged and synced.
