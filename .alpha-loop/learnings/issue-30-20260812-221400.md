# Issue #30 — submodule-safe browser daemon ownership

## Surprise

The daemon wrapper's Git-common-directory heuristic was correct for standalone
and linked-worktree OSS runs, but a submodule inside a superproject worktree
resolves that directory into the consumer's `.git/worktrees/.../modules`
metadata. A valid daemon rooted in the OSS checkout was therefore rejected.

## Lesson

Dependency-consumer verification is a distinct runtime posture. When ownership
checks use Git metadata, trust the current checkout root in every posture and
add the wider Git-common root only when it demonstrably belongs to the same
ordinary or linked-worktree repository. Never treat a superproject's `modules`
metadata directory as an executable ownership root.

## Regression

The repository posture suite now creates a real local superproject and OSS
submodule, launches a fake agent-browser daemon under that checkout, and proves
the wrapper terminates it while retaining the unrelated-process refusal path.
