## What Worked
- Generated a harmless server-owned fact and kept the fresh-chat prompt limited to an opaque marker.
- Made completion depend on the exact ordered import, query result ID, and lineage audit chain rather than accepting typed answer text.
- Added explicit transport and client identities to audit events and injected per-client identities into managed MCP launchers.
- Reused the installer capability matrix to fail unsupported localhost and WSL combinations before mutation.
- Kept migration verification memory-backed and browser verification on a same-origin in-memory fixture, preserving stable data and disk space.

## What Failed
- The first public-boundary run rejected the diagnostic name `permission` because that term belongs to an enterprise-only capability family; renaming the local failure to `access` preserved the distinction without crossing the OSS boundary.
- Review found that generic `mcp` evidence could not distinguish Codex from Claude Code. Exact client identity is now required on all three proof events, with a wrong-client regression.
- The pinned browser screenshot RPC stalled and wrote no PNG, reproducing known issue #44. Bounded project-daemon recovery preserved semantic, viewport, focus, motion, request, and axe evidence.
- The browser tool held one responsive sidebar transition at virtual time zero; finishing that observed transition allowed the 375px semantic interaction to proceed. Reduced-motion behavior independently verified at 1ms.

## Patterns
- Treat onboarding proof as a persisted evidence state machine, not a boolean supplied by the UI.
- Bind proof events to tenant, content ID, event order, transport, and client identity.
- Keep answer-bearing text out of the prompt used in the fresh context.
- Derive tutorial support from the installer matrix, then reject identity-ambiguous combinations even if each client is independently installable.

## Anti-Patterns
- Do not accept a model's typed answer, a generic transport label, or an unverified browser header as evidence that a selected client invoked a tool.
- Do not describe remote or host/guest localhost paths as supported when they cannot be exercised from the installed runtime.

## Suggested Skill Updates
- Add client identity, not only transport identity, to cross-client MCP verification checklists.
- Treat answer-free prompt inspection and ordered lineage evidence as mandatory for memory-onboarding acceptance.
