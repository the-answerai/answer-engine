## What worked

- Converted the canonical worker browser skill to `agent-browser` and kept both
  harness outputs generated from that single source.
- Pinned the browser CLI in the workspace and invoked it through `pnpm exec`,
  removing reliance on an ambient global command or network-time `npx` install.
- Made live verification instructions explicit while retaining Playwright only
  for automated E2E tests.
- Added a host-side Alpha Loop browser preflight and a fixed, short `/tmp`
  socket/profile so linked-worktree workers connect to an already-running
  Chrome instead of attempting a forbidden sandbox launch.

## What failed

- The previous setup synced `playwright-cli`, whose daemon attempted to write
  into a home cache outside the worker sandbox during #9.
- A first linked-worktree regression exposed two additional assumptions: the
  socket defaulted to the home directory, and macOS denied launching Chrome
  from inside Codex's workspace-write sandbox even after the socket moved.
- The first successful shared-daemon screenshot resolved its relative output
  against the daemon's original worktree. The wrapper now pins screenshot
  output to each calling worktree.
- The first PR CI run failed because `.alpha-loop.yaml` was modified locally
  but omitted from the commit by staging `.alpha-loop/` (a different path).
  The new setup-command assertion caught the missing tracked configuration in
  CI. Always inspect `git status` after committing dotted sibling paths.
- The preserved #9 worktree had a pre-pin `node_modules` layout. Pnpm needed to
  replace it but aborted without a TTY, so the pinned browser binary remained
  unavailable. `browser:prepare` now refreshes the frozen dependency graph with
  `CI=true` before launching Chrome, covering fresh and resumed worktrees.

## Reusable lesson

Tool choice and writable runtime state are part of verification posture, not
ambient environment assumptions. Assert them in repository tests before an
unattended UI issue begins.
