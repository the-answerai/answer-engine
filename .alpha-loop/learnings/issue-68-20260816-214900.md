## What Worked

- Extracted legacy adoption into one installer-owned API used by both the CLI
  install flow and Electron controller, keeping ownership validation consistent.
- Made inspection read-only and completed every validation before atomically
  adding channel metadata and the ownership marker.
- Moved adoption ahead of Docker/model/port preflight, so unrelated development
  services cannot block a no-start, no-bind metadata operation.
- Added runtime mode and explicit external-action results to the narrow desktop
  contract, making fixture truthfulness consistent across renderer, tray, and
  IPC rather than relying on copy alone.
- Kept production URL selection at the API-served origin while retaining Vite
  ports behind one explicit development option.

## What Failed

- The first standalone installer type-check ran before generated CLI package
  declarations existed. Building `@answer-engine/cli` first resolved the normal
  workspace build-order dependency; the complete repository verification then
  passed in its canonical order.
- The managed macOS worker built Electron but the OS terminated the GUI process
  with `SIGABRT` before its CDP port opened. The existing prelaunched Chrome
  session could load the renderer, but it could not retroactively install the
  required pre-navigation bridge. Closing that session exposed the expected
  sandbox restriction: Chrome could not relaunch, and the wrapper refused to
  reset it without permitted process inspection. No raw CLI or no-sandbox
  workaround was used.

## Patterns

- A simulated controller should report simulated mode plus false installed and
  health state; presentation-only labels are insufficient when other consumers
  such as trays derive status independently.
- External side effects need result values that distinguish successful action
  from intentionally disabled behavior. A resolved no-op promise is not proof
  that anything opened.
- Adoption is a metadata transaction, not an installation preflight. Validate
  project, channel, path, file type, syntax, and isolation, then avoid unrelated
  model/runtime/port gates that the operation does not use.
- Browser-preparation state must include any pre-navigation fixture bridge before
  the worker begins; it cannot be added reliably after the shared session opens.

## Anti-Patterns

- Do not infer a real healthy service from fixture controller state.
- Do not rewrite packaged UI origins to development-only ports by default.
- Do not route legacy users through Start and let the ownership guard become
  their first explanation of adoption.
- Do not weaken lifecycle ownership checks to make adoption convenient.
