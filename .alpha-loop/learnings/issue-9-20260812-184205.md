## Outcome

#9 reached mandatory live UI verification after creating a substantial but
uncommitted implementation. The worker selected `playwright-cli`, then failed
when its daemon attempted to create `~/Library/Caches/ms-playwright` outside the
Codex linked-worktree sandbox. The supervisor interrupted the run once; #9's
worktree was preserved and #10 did not start.

## Root cause

The canonical Alpha Loop template bundle synced `playwright-cli` but did not
include the repository-required `agent-browser` skill. Worker instructions said
only to perform browser verification, so skill selection was ambiguous. The
configured browser profile also used a home-directory path instead of a path
writable by linked-worktree agents.

## Reusable lesson

Unattended UI verification needs one explicit browser CLI, the matching synced
skill, and a profile path inside the worker sandbox. Tests must enforce all
three. On browser service or sandbox failure, preserve the active worktree and
do not advance the ordered epic queue.
