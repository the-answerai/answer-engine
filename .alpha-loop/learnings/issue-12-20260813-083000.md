# Issue #12 acceptance learning

- Treat a real-history inventory as an append-only minimum, then compare stored
  data to the latest authoritative scan rather than a frozen cursor count.
- Stream lightweight database rows and fetch full manifests only for the
  deterministic sample; aggregating thousands of large manifests can exhaust a
  small installer-managed PostgreSQL container.
- A final acceptance issue needs a durable integrated execution record, not
  only a narrow verifier. Record installer idempotence, service/model state,
  browser mutations, REST/MCP grounding, enterprise pinning, and final gates.
- Browser acceptance can expose regressions outside the changed component. The
  shared faint-text token missed WCAG AA by 0.11 and was fixed at the semantic
  token rather than patched per component.
- Process-lifecycle tests must supply a deterministic process inspector. Tests
  that fall through to macOS `/bin/ps` cannot run in a managed worker sandbox.
