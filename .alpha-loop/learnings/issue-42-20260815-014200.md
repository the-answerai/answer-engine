# Issue #42 — one-prompt installer and capability preflight

## Preflight needs two independent signals

A useful preflight distinguishes capability severity from whether installation
may proceed. Constrained memory or a missing local model runtime can be a
warning with a reduced-local or explicit cloud fallback, while missing Docker,
occupied ports, or an unsupported platform must block mutation. Keeping ordered
checks and a separate `blocking` field makes both human and JSON output precise.

## Idempotency requires durable in-progress lifecycle state

Comparing generated bytes avoids needless rewrites, but upgrade and rollback
also need to survive interruption after the environment changes and before the
runtime becomes healthy. A persisted pending transition retains the original
release and target so retries converge instead of becoming false no-ops or
toggling releases.

## Supply-chain checks belong next to the assets

The package now carries a runtime-validated release manifest beside the exact
templates it authenticates. Verifying tag/version agreement, immutable prompt
URLs, digest-pinned third-party images, and template SHA-256 values immediately
before scaffold or image pulls catches drift before any installer mutation.

## Documentation drift should fail in tests

The shortest reliable way to expose a canonical copy-paste prompt in multiple
surfaces is to bracket the exact block and compare bytes in a repository test.
This catches text, version, URL, and command drift without introducing a second
hand-maintained source.
